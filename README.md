# WEATHER LAB · METAR Fresh

Six views: hourly airport METAR plots, regional Maps, experimental AI Forecast, two-hour KMPX radar, Central Minnesota satellite, and the NWS Hopkins forecast. Observations and Maps use official airport METARs only.

## Deploy to a new Google Cloud project

Open Google Cloud Shell, clone this branch, and run `bash start-fresh.sh`.
The script creates **Weather Lab METAR Fresh**, links an active billing account, builds and uploads the application using Google Cloud Build, deploys public `weather-lab` and private `weather-collector` Cloud Run services, and imports twelve hours of NOAA METAR history. No ZIP upload or paid weather API is required. Cloud Build uses a dedicated `weather-builder` service account and regional user-owned build/log buckets. Cloud Shell's local Docker daemon is not used unless you explicitly set `WEATHER_BUILD_MODE=docker`.

Before submitting a build, setup runs read-only checks of the signed-in caller's effective build and service-account permissions. Missing access is printed with the permission and resource names; setup then stops before submitting a build. This check never grants IAM roles. Access tokens remain in memory and are never printed or saved.

If multiple billing accounts are available, set `WEATHER_BILLING_ACCOUNT=YOUR_ACCOUNT_ID` before running. The selected account must be open and accessible to your signed-in Google account. Google Cloud compute, storage and scheduling charges still apply.

The project ID is saved in `$HOME/weather-lab-metar-project.txt`. Rerunning the script resumes that project instead of creating extras. To deliberately create a different project, supply a new unused `WEATHER_PROJECT` ID. The script does not restore or delete old projects. Setup may take several minutes; keep Cloud Shell open until it prints the final URL. New-project permission propagation is retried a bounded number of times. If a command fails, rerun the same script; persistent permission errors still require fixing your Google account's access.

## METAR observations

Only routine NOAA Aviation Weather Center METARs are accepted, including reporting ASOS/AWOS airport sites. The Upper Midwest bounds are 40–50°N, 100–85°W. KCFE/KFCE and KSGS retain the existing station exclusions.

Collection runs once an hour at **:02**. For each hour, accepted report timestamps are strictly **:50:00–:59:59 of the previous hour**. Prefer the report nearest :53; ties prefer newer observations and then corrections. An 11:53 report is labeled noon and retains 11:53 in its popup. SPECI and rapid MADISHF reports, out-of-window sites and missing values are omitted. These strict rules intentionally reduce station coverage.

Each collection queries the previous hour's NOAA archive, so a newer SPECI or off-window report cannot hide an eligible routine METAR in a latest-only cache. AWC's 400-result cap is handled by splitting geographic queries; requests are globally rate limited to fewer than 100/minute. Collection runs once per hour even when several capped queries are needed to retrieve that hour. Browser Refresh only reads prepared data.

Twelve real hourly frames are backfilled during setup. History remains in a private Cloud Storage bucket when Cloud Run scales to zero. No synthetic times or station values fill gaps. Failed collections retain saved data, and the page shows delayed-update status. The initial import pauses the hourly writer, resumes it on exit, and immediately runs it afterward.

Plots show temperature and dew point in °F and wind in mph, with arrows pointing toward wind flow. The central circle now shows reported sky cover: open for CLR/SKC, quarter-filled FEW, half-filled SCT, three-quarter BKN and solid OVC. Fractional fills represent METAR categories (1–2, 3–4 and 5–7 eighths), not exact measured oktas. The wind arrow has a longer, thicker shaft and solid arrowhead outside the circle; adjacent labels move just enough to clear its direction. Blue wind speed matches the temperature text size; calm winds have a second ring. Temperature and dew point sit close to the circle on the left, blue wind speed is at the lower right, and the lowest BKN/OVC base appears in black at the upper right in hundreds of feet AGL, such as `27` for 2,700 feet or `03` for 300 feet. Cloud height matches the temperature/dew-point text size. Bases above 9,900 feet retain three digits for accuracy. Obscured sky uses an X and a separately labeled VV value; unknown sky uses ?. Popups include all layers and exact heights. Existing history obtains cloud information from its saved raw METARs without new archive downloads. Regional collection discovers airport IDs from the NOAA station catalog and queries explicit station batches, splitting capped responses, because NOAA bbox queries can omit stations even below the cap. The version update repairs saved twelve-hour history once; subsequent collections remain hourly. Zoom reveals more non-overlapping stations; the searchable list includes plots hidden to prevent overlap. Actual METAR timestamps and raw reports remain in popups. Basic range, coordinate and dew-point checks apply; these do not constitute complete instrument QC.

## Maps

The Maps tab covers 39–51°N and 108–80°W, including the full Dakotas with a surrounding station buffer. It provides temperature, dew point, and wind speed/direction analysis with a twelve-hour slider and playback. Zoom buttons use 0.1-level steps, and wheel zoom is slowed for finer control. Temperature and dew point reuse the same earlier reference palette in 5°F bands; wind uses the original 5 mph bands with direction arrows. Only state/county boundaries, contours, and wind vectors are drawn, with no station dots or city names.

The coverage upgrade imports the wider twelve-hour airport history once, then returns to one-hour collections. The existing :02 METAR collector builds missing map hours from saved observations, without re-downloading history. Unchanged hours reuse immutable image/contour assets. Map preparation is isolated from observation collection; a map failure preserves the observation data and previous map index. The public page only reads prepared maps. The first update fills all available twelve saved hours; ordinary updates prepare only changed/new hours.

Analysis uses independent per-field neighbor screens, spatial de-clustering, a 40% maximum station weight, and vector-component interpolation for winds. Sparse interiors use an adaptive broader blend: the nearest station must be within 180 km and the third within 250 km, with contributions tapering to zero at 300 km. Cells remain inside the station network's convex hull; unsupported cells stay transparent. These broader estimates can miss local gradients and are not official instrument QC. The status line reports the share of supported grid cells beyond the former 65 km nearest / 110 km third-neighbor limits, alongside QC and limited-neighbor counts. This interpolation upgrade rebuilds all twelve saved hours without refetching reports. Source reports remain unchanged on Observations.

## Experimental AI Forecast

The `ai-forecast-20261016` branch adds a separate AI Forecast tab with temperature, dew point and vector wind at **every hour from +1 through +24**. The default view covers the same 39–51°N, 108–80°W region as the METAR analysis. The pooled model predicts at all eligible currently reporting airports in that region, including airports outside its supervised training subset. It uses the existing 5°F / 5 mph palettes and state/county boundaries. Sparse interiors use the same broader interpolation as Maps; unsupported edges and areas lacking usable inputs remain blank. Smooth images do not imply equally fine forecast skill. Forecast times follow the observation labels: a target labeled 22:00 uses the eligible 21:50–21:59 report.

A trained regional model ships in `ai_bundle/model.json.gz.b64`, with held-out scores in `ai_bundle/report.json`. Deployment needs no training job. The existing :02 station collector performs portable CPU inference from its twelve saved snapshots and prepares all 72 map layers. Public APIs only read status and saved assets. Normal browser visits never start downloads, map production or training. Failed preparation retains the last published forecast. Numerical forecasts as issued are saved privately for 30 days under `ai/issued/` for prospective evaluation; they never enter observation history. Legacy pilot assets stay readable during upgrade, while an older privately retrained v1 model cannot override the regional v2 bundle.

Training uses 120 days (June 18 through October 15, 2026) of routine airport reports from the IEM archive, restricted to :50–:59 and the same nearest-:53 preference. Special and rapid HFMETAR reports are excluded. `ai_station_network.json` selects 180 geographically distributed airports from the eligible live network, retaining network-hull and original pilot airports and then using farthest-point geographic sampling. The archive supplied 490,624 eligible reports from 177 airports; unavailable historical sites are disclosed in the model report. Live prediction can still use other eligible reporting sites. Only range, coordinate, time and dew-point consistency checks apply; this is not complete instrument QC. Features use current and lagged reports, five nearby airports' values/trends, altimeter pressure trends, coordinates, calendar cycles and forecast hour. No radar, satellite, upper-air or numerical weather-model guidance enters this experiment.

Four pooled histogram gradient boosted regressors predict temperature, dew point and east/north wind changes, explicitly conditioned on lead hour. All 24 leads are predicted by the model; intermediate hours are not interpolated between the old five products. Training examples are sampled separately for each hour and target, with up to 8,000 cases per hour per target to bound CPU use. Features gather only the five nearest neighbors rather than multiplying a dense station matrix for every historical time.

Fit, blend selection and test dates are separated chronologically (75% / 12.5% / 12.5%), with target timestamps embargoed at the boundaries. In addition, a deterministic geographic group of 32 airports is excluded from supervised fitting and blend selection; its contemporaneous observations remain available as causal neighboring inputs, as in operation. The report includes separate errors for those held-out sites. Hour-specific blend weights between the model and persistence are selected only on earlier validation dates. The last approximately fifteen days are held out for reporting, not model selection. A zero weight is disclosed as an unchanged-value fallback. The UI reports average errors alongside persistence; wind vector error accounts for direction and speed. These averages are not uncertainty bounds or proof of better skill than NWS/HRRR. Archive reports may contain retrospective corrections; prospective verification is still required.

The training dependency is separate: `pip install -r requirements-ai.txt`, then `python train_ai.py --days 120`. Downloads are cached under ignored `training/`; responses are size-limited and IEM requests spaced by at least one second. The trainer checks exported numeric-tree predictions against scikit-learn, including missing-value inputs and all forecast hours. Web/collector images do not install scikit-learn or execute serialized Python models. The local regional training/test pass took approximately 52 seconds after downloading the archive; Cloud Run timing and costs vary.

For optional manual Google Cloud retraining after deployment, run `bash train-ai.sh YOUR_EXISTING_PROJECT_ID`. It builds a separate CPU trainer and starts one private Cloud Run Job with 4 vCPU / 8 GiB, a 30-minute task timeout, a 25-minute internal runtime limit and zero retries. It does not create recurring training or grant IAM roles. The AI Forecast tab polls saved progress, stage counts, elapsed time and a stage-specific ETA while open. Container building occurs before training progress starts. The job saves the model privately, then triggers the existing station collector to update all 24 forecast hours. The old model/forecasts remain available if training fails. Runtime limits bound the task, not the entire account bill; builds, storage and normal website operation have their own charges.

## Loading

Opening the page preloads the latest map index, all three latest map images, and the latest radar scan alongside observations. A bounded browser cache saves prepared data and immutable assets between visits. Saved views retain their real report/scan timestamps and display a refresh message while fresh data is checked. Concurrent reads share one network request; cached data is retained if a refresh fails. JSON histories are gzip-compressed for smaller transfers. First-time visits still need the initial network transfer and any server startup; preloading and caching reduce later tab and repeat-visit waits.

## Radar, satellite and forecast

- KMPX native Level II 0.5° reflectivity, the original continuous COD-style green-to-yellow/orange/red/magenta gradient, and all available scans in the rolling **two-hour** window. No personal-location dots. Faint major highways have no city labels. Radar collection runs every minute; native scan timing is controlled by NWS.
- Central Minnesota GOES-East True Color, Day Cloud Phase and Nighttime Microphysics. Twenty-four images per product, original colors, state/county overlays, manual timeline. Prepared every five minutes.
- Official NWS day/night point forecast for Hopkins at 44.9244, -93.4140, checked at :00 and :30 each hour and retaining NWS wording and issuance time.

Both Cloud Run services scale to zero and have a maximum of one instance. There are four Cloud Scheduler jobs. Only the web service is public; collection requires authenticated invocation. The dedicated private bucket removes replaceable imagery after one day; live hourly history is retained.

## Local checks

Install `requirements.txt`, then run `python -m unittest discover -s tests -v` and `node tests/metar_views.test.js`. Additional JS checks cover radar history, highways and tabs. `python app.py` starts the web view; native radar requires the collector and `WEATHER_DATA_BUCKET`.
